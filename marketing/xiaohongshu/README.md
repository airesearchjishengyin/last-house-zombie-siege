这一组共 5 张 3:4 竖图，按“项目钩子 → 地图机制 → 决策怎么落地 → 可调玩法 → 试玩与开源”排序。封面先说清这是什么游戏，后续每页用一张当前版本实机画面支持一个具体信息。建议直接发布时在标题、首段和图片文字中自然使用“AI 游戏 / 僵尸生存 / 开源游戏”等用户会主动搜索的词，不要重复堆词。

平台没有公开能保证爆款的固定公式，网上常见的“流量池阈值”“黄金时间”“互动权重配方”多为第三方推测或营销内容，不能当作官方规则。这份稿件采用可验证的内容方法：

- **按数据复盘：**发布后在创作服务平台查看曝光、互动和受众反馈；比较不同主题的表现，不预设单一指标或保证结果。

### 正文

我一直想做一个“电子斗蛐蛐”式的小实验：给双方不同的决策方式，看它们在同一张地图里会怎么打。现在它已经变成一个能直接玩的浏览器游戏了。

玩法是人类小队深入僵尸巢穴，在 360 秒内搜索房间、处理沿途感染者，最后找出并摧毁藏在巢穴里的小型母体。另一种任务是守住种子库，顶过 6 波尸潮。人类有机枪、步枪、狙击和霰弹兵；僵尸按规则追击、绕墙，碰到人类就会同化。

地图我也重新做了一轮：回声迷宫有环形路线和多个巢室，蜂巢地堡用窄廊连接密室；黑水河谷被水面分成两岸，过河必须走桥。墙会挡人和子弹，水挡移动但不挡射击，所以走哪条路会影响交战。

我把开源的 Laya typed-decision checkpoint 接到人类指挥流程里。它从当前可执行的候选动作中选一种，游戏把选择映射成分队搜索、定点压制、侧翼包抄、突击母体、集合补给或环形守卫。比如选择“侧翼包抄”时，机枪和狙击手压制标记目标，步枪和霰弹小队从两侧绕行；路线、目标和执行人数会显示在战场上。

开局前还能调人类数量、感染者初始数量、血量和增援速度；弹药有无限与有限两种模式，有限模式要定期去补给点。掩体可以自己编辑，也支持导入导出地图 JSON。

也说明一下模型边界：这里用的是通用开源决策 checkpoint，目前没有拿本游戏数据专项训练。状态结构、合法候选动作以及动作如何控制队伍，都是项目代码定义的；它不是已经学会高水平射击战术的专用模型。

我做这些机制的主要目的，是让“模型选了什么”在画面中有可观察的后果，而不是只显示一句战术文本。接下来我还会继续看不同地图和敌情下，小队路线与任务完成情况有没有明显变化。
